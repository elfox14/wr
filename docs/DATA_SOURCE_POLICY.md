# World Cup Exchange — Data Source Policy v2

## 1) الهدف

هذه الوثيقة تحدد مصدر كل نوع بيانات داخل منصة World Cup Exchange، وترتيب أولوية المزودين، ومتى يسمح للمصدر الاحتياطي بتعديل بيانات المباراة أو التأثير على حركة السعر.

القاعدة الأساسية:

**قاعدة بيانات المنصة هي مصدر الحقيقة للواجهة، وليس أي API خارجي مباشرة.**

أي API خارجي يستخدم فقط لجلب أو تأكيد أو إثراء البيانات، ثم تحفظ النتيجة داخل قاعدة البيانات المحلية أو سجل تحقق داخلي.

---

## 2) أدوار مزودي البيانات

| المزود | الدور الأساسي | هل يستخدم للـ live؟ | هل يؤثر على السعر؟ |
|---|---|---|---|
| ISPORTS | مصدر live والأنيميشن وتحديثات المباراة اللحظية | نعم | نعم، لكن فقط للأحداث اللحظية المسموح بها |
| TheStatsAPI | مصدر تحقق وإثراء بعدي/إداري: نتائج، إحصائيات، أحداث، xG، تشكيلات إن توفرت | لا كقراءة مباشرة من الواجهة | لا، إلا بعد مراجعة داخلية وقواعد منفصلة |
| football-data.org | مصدر احتياطي لتأكيد النتائج والحالة وجدول المباريات | لا كمصدر live أساسي | نعم بشروط محدودة، أو للتأكيد فقط |
| TheSportsDB | صور، شعارات، بروفايلات فرق ولاعبين | لا | لا |
| API-Football | مصدر رياضي عميق مؤجل/مشروط | ليس حاليًا | فقط إذا تم تفعيله رسميًا كمصدر موثوق |

| نوع البيانات | المصدر الأول | المصدر الثاني | الاستخدام |

| Live score | ISPORTS | TheStatsAPI / API-Football إذا تم تفعيلهما | تحديث حالة المباراة أثناء اللعب |
| Match status | ISPORTS أثناء المباراة | football-data.org / TheStatsAPI للتأكيد | تحديث SCHEDULED / IN_PLAY / FINISHED |
| Final score | football-data.org أو TheStatsAPI للتأكيد | ISPORTS كمصدر لحظي | اعتماد النتيجة النهائية |

| Match events | ISPORTS أثناء المباراة | TheStatsAPI للتأكيد/الإثراء | أهداف، بطاقات، تبديلات، VAR، أحداث مهمة |
| Match stats | ISPORTS أثناء المباراة | TheStatsAPI بعد المباراة | استحواذ، تسديدات، ركنيات، كروت، xG إن توفر |
| Lineups/formations | مصدر رسمي/تحريري | TheStatsAPI للتأكيد | عرض التشكيل والخطة |

| Player performance | TheStatsAPI أو API-Football إذا تم تفعيله | ISPORTS إذا كانت بياناته كافية | تقييم أداء اللاعبين |
| Market price movement | محرك التسعير الداخلي | لا يوجد | لا يتحرك السعر مباشرة من API بدون قواعد |

## 4) سياسة TheStatsAPI

TheStatsAPI يستخدم فقط في وضع آمن:

1. **Verify-only افتراضيًا.**
2. لا يتم حذف أو استبدال البيانات القديمة تلقائيًا.
3. أي اختلاف يتم تسجيله في `DataVerificationLog` أولًا.
4. لا يتم تطبيق تصحيح آمن إلا عند تعطيل `THE_STATS_API_VERIFY_ONLY` صراحةً وتشغيل `apply=true&dryRun=false` من endpoint إداري.
5. التصحيح الآمن محدود جدًا: حالة المباراة والنتيجة النهائية فقط، ولا يتم إلا عند وجود مصدر واضح.
6. الإثراء مثل xG، shot maps، lineups، player stats يبدأ كسجل تحقق أو rawData قبل عرضه في الواجهة.

### بيانات ممنوعة من TheStatsAPI

يمنع استخدام أو تخزين أو عرض أي من الآتي:

- odds
- betting
- bookmakers
- Bet365
- Pinnacle
- Betfair
- Kambi
- Asian handicap
- BTTS
- DNB
- totals / over-under
- أي endpoint أو query متعلق بالمراهنات أو احتمالات الرهان

الكود يجب أن يحتوي blocklist تمنع هذه المسارات قبل أي طلب خارجي.

---

## 5) قاعدة تعديل السعر

لا يسمح لأي مصدر خارجي بتعديل السعر مباشرة.

أي تعديل سعر يجب أن يمر عبر:

1. حدث واضح.
2. مصدر معروف.
3. قاعدة impact داخلية.
4. حد تذبذب volatility cap.
5. سجل marketNews أو priceHistory.

---

## 6) متى يسمح لـ ISPORTS بتحريك السعر؟

يسمح لـ ISPORTS بتحريك السعر لأنه مصدر live الحالي، لكن فقط في الحالات التالية:

- هدف جديد أثناء المباراة.
- تغير واضح في النتيجة.
- بداية المباراة أو تحولها إلى IN_PLAY.
- نهاية المباراة إذا لم يكن هناك مصدر تأكيد متاح بعد.

لا يسمح لـ ISPORTS وحده بتوليد تقييم أداء نهائي للاعبين إلا إذا كانت بيانات player stats مكتملة ومختبرة.

---

## 7) متى يسمح للمصادر المؤكدة بتصحيح النتيجة؟

football-data.org وTheStatsAPI مصادر تأكيد وليست live أساسيًا.

يسمح لهما بالتصحيح فقط في الحالات التالية:

### الحالة الأولى: تأكيد هدف لم يكن مسجلًا محليًا

إذا كانت المباراة موجودة محليًا، والمصدر أرجع نتيجة أعلى من النتيجة المحلية، يتم تسجيل الاختلاف أولًا، ولا يتم إنشاء تأثير سعري إلا وفق قواعد داخلية مستقلة.

### الحالة الثانية: تأكيد نهاية المباراة

إذا كانت المباراة محليًا IN_PLAY أو SCHEDULED، والمصدر أرجع FINISHED، يمكن تحديث حالة المباراة بعد التسجيل في `DataVerificationLog`.

### الحالة الثالثة: تصحيح نتيجة نهائية

إذا كان هناك اختلاف بين النتيجة المحلية والنتيجة النهائية في المصدر، يتم تسجيل الاختلاف. التصحيح التلقائي لا يتم إلا عند تشغيل safe apply صراحةً.

---

## 8) متى يكون المصدر الاحتياطي للتأكيد فقط؟

يكون للتأكيد فقط في الحالات التالية:

- المباراة غير موجودة محليًا و`createMissing=false`.
- النتيجة مطابقة للنتيجة المحلية.
- الحالة فقط تغيرت من SCHEDULED إلى TIMED أو العكس.
- المصدر لا يحتوي تفاصيل أحداث كافية.
- يوجد تعارض واضح مع ISPORTS أثناء مباراة live لم تنته بعد.
- البيانات من endpoint عام ولا توجد ثقة كافية في الربط بين الفريقين.

في هذه الحالات يتم تحديث أو تسجيل الحالة دون إنشاء market event مؤثر.

---

## 9) متى لا يسمح للمصدر الاحتياطي بتغيير السعر؟

لا يسمح للمصدر الاحتياطي بتغيير السعر إذا:

- المباراة لا تزال live ولم تنته.
- النتيجة من المصدر الاحتياطي أقل من النتيجة المحلية.
- لم يتم العثور على الفريقين بثقة داخل قاعدة البيانات.
- الحدث قد تم تطبيقه سابقًا بنفس `localeGroupKey`.
- التغيير سيؤدي إلى تكرار هدف أو تكرار تأثير سعري.
- لم يتم تفعيل `applyMarketEvents=true`.

---

## 10) سياسة التعارض بين المصادر

عند التعارض:

1. أثناء المباراة: ISPORTS له الأولوية للـ live.
2. بعد نهاية المباراة: football-data.org أو TheStatsAPI يستخدمان للتأكيد، مع تسجيل الاختلافات.
3. الصور والبروفايلات: TheSportsDB أو المصدر التحريري له الأولوية.
4. القوائم الرسمية: مصادر رسمية أو Data Hub معتمد فقط.
5. الأسعار: محرك التسعير الداخلي له الأولوية دائمًا.

---

## 11) سياسة حماية الحصص

- لا يتم استدعاء live provider إلا عند وجود مباريات اليوم أو مباريات قريبة.
- يتم استخدام throttle مع ISPORTS.
- TheStatsAPI يستخدم من admin/cron فقط، وليس من الواجهة العامة.
- football-data.org يستخدم كطلب مجمع حسب التاريخ أو المسابقة.
- TheSportsDB يستخدم في admin sync أو enrichment، وليس في كل زيارة للواجهة.
- الواجهة تقرأ دائمًا من قاعدة البيانات المحلية.

---

## 12) مبدأ التتبع

أي بيانات تؤثر على السعر أو النتيجة أو الثقة يجب أن تكون قابلة للتتبع:

- provider
- providerMatchId
- localMatchId
- eventType أو field
- scoreBefore
- scoreAfter
- priceBefore
- priceAfter
- localeGroupKey
- rawData أو sourceUrl عند الحاجة

بدون هذه المعلومات، لا يجب إنشاء تأثير سعري تلقائي.

---

## 13) سياسة AdSense والقانون

المنصة رياضية وترفيهية فقط:

- لا تعرض مراهنات.
- لا تعرض odds أو احتمالات رهان.
- لا تروج لأي bookmaker.
- لا تسمح بإيداع أو سحب أموال.
- لا تقدم توصيات مالية أو ربح حقيقي.
- الأسعار والمؤشرات داخل الموقع افتراضية وترفيهية فقط.

أي مصدر بيانات يحتوي betting أو odds يجب تجاهل هذا الجزء بالكامل.

---

## 14) القرار الحالي

الوضع الحالي المعتمد:

**ISPORTS = live source**  
**TheStatsAPI = verification and enrichment source only**  
**football-data.org = confirmation and backup source**  
**TheSportsDB = media and profile enrichment source**  
**API-Football = conditional future provider**  
**Database = platform source of truth**  
**Pricing engine = business value layer**

---

## 15) قاعدة تنفيذ مستقبلية

أي تعديل مستقبلي في مصادر البيانات أو تحريك السعر يجب أن يلتزم بهذه الوثيقة أولًا.

إذا احتاج تعديل قادم إلى مخالفة هذه السياسة، يجب تحديث هذه الوثيقة في نفس التعديل مع توضيح السبب.
