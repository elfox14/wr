# World Cup Exchange — Data Source Policy v1

## 1) الهدف

هذه الوثيقة تحدد مصدر كل نوع بيانات داخل منصة World Cup Exchange، وترتيب أولوية المزودين، ومتى يسمح للمصدر الاحتياطي بتعديل بيانات المباراة أو التأثير على حركة السعر.

القاعدة الأساسية:

**قاعدة بيانات المنصة هي مصدر الحقيقة للواجهة، وليس أي API خارجي مباشرة.**

أي API خارجي يستخدم فقط لجلب أو تأكيد أو إثراء البيانات، ثم تحفظ النتيجة داخل قاعدة البيانات المحلية.

---

## 2) أدوار مزودي البيانات

| المزود | الدور الأساسي | هل يستخدم للـ live؟ | هل يؤثر على السعر؟ |
|---|---|---|---|
| ISPORTS | مصدر live والأنيميشن وتحديثات المباراة اللحظية | نعم | نعم، لكن فقط للأحداث اللحظية المسموح بها |
| football-data.org | مصدر احتياطي لتأكيد النتائج والحالة وجدول المباريات | لا كمصدر live أساسي | نعم بشروط محدودة، أو للتأكيد فقط |
| TheSportsDB | صور، شعارات، بروفايلات فرق ولاعبين | لا | لا |
| API-Football | مصدر رياضي عميق مؤجل/مشروط | ليس حاليًا | فقط إذا تم تفعيله رسميًا كمصدر موثوق |

---

## 3) مصدر كل نوع بيانات

| نوع البيانات | المصدر الأول | المصدر الثاني | الاستخدام |
|---|---|---|---|
| Live score | ISPORTS | API-Football إذا تم تفعيله | تحديث حالة المباراة أثناء اللعب |
| Match status | ISPORTS أثناء المباراة | football-data.org للتأكيد | تحديث SCHEDULED / IN_PLAY / FINISHED |
| Final score | football-data.org للتأكيد | ISPORTS كمصدر لحظي | اعتماد النتيجة النهائية |
| Fixtures | football-data.org | ISPORTS / API-Football | إنشاء أو تحديث جدول المباريات |
| Team images | TheSportsDB | بيانات provider إن وجدت | عرض بصري فقط |
| Player images | TheSportsDB | صورة الفريق fallback | عرض بصري فقط |
| Team/player profiles | TheSportsDB | تحرير داخلي | إثراء صفحات العرض |
| Player performance | API-Football إذا عاد | ISPORTS إذا كانت بياناته كافية | تقييم أداء اللاعبين |
| Market price movement | محرك التسعير الداخلي | لا يوجد | لا يتحرك السعر مباشرة من API بدون قواعد |

---

## 4) قاعدة تعديل السعر

لا يسمح لأي مصدر خارجي بتعديل السعر مباشرة.

أي تعديل سعر يجب أن يمر عبر:

1. حدث واضح.
2. مصدر معروف.
3. قاعدة impact داخلية.
4. حد تذبذب volatility cap.
5. سجل marketNews أو priceHistory.

---

## 5) متى يسمح لـ ISPORTS بتحريك السعر؟

يسمح لـ ISPORTS بتحريك السعر لأنه مصدر live الحالي، لكن فقط في الحالات التالية:

- هدف جديد أثناء المباراة.
- تغير واضح في النتيجة.
- بداية المباراة أو تحولها إلى IN_PLAY.
- نهاية المباراة إذا لم يكن هناك مصدر تأكيد متاح بعد.

لا يسمح لـ ISPORTS وحده بتوليد تقييم أداء نهائي للاعبين إلا إذا كانت بيانات player stats مكتملة ومختبرة.

---

## 6) متى يسمح لـ football-data.org بتحريك السعر؟

football-data.org مصدر تأكيد وليس live أساسيًا.

يسمح له بتحريك السعر فقط في الحالات التالية:

### الحالة الأولى: تأكيد هدف لم يكن مسجلًا محليًا

إذا كانت المباراة موجودة محليًا، وfootball-data.org أرجع نتيجة أعلى من النتيجة المحلية، يتم إنشاء حدث سعر بعنوان “هدف مؤكد”.

### الحالة الثانية: تأكيد نهاية المباراة

إذا كانت المباراة محليًا IN_PLAY أو SCHEDULED، وfootball-data.org أرجع FINISHED، يتم تحديث حالة المباراة إلى FINISHED.

### الحالة الثالثة: تصحيح نتيجة نهائية

إذا كان هناك اختلاف بين النتيجة المحلية والنتيجة النهائية في football-data.org، يتم تحديث النتيجة، لكن يفضل ألا يتم تحريك السعر تلقائيًا إلا إذا كان `applyMarketEvents=true`.

---

## 7) متى يكون football-data.org للتأكيد فقط؟

يكون للتأكيد فقط في الحالات التالية:

- المباراة غير موجودة محليًا و`createMissing=false`.
- النتيجة مطابقة للنتيجة المحلية.
- الحالة فقط تغيرت من SCHEDULED إلى TIMED أو العكس.
- المصدر لا يحتوي تفاصيل أحداث كافية.
- يوجد تعارض واضح مع ISPORTS أثناء مباراة live لم تنته بعد.

في هذه الحالات يتم تحديث أو تسجيل الحالة دون إنشاء market event مؤثر.

---

## 8) متى لا يسمح للمصدر الاحتياطي بتغيير السعر؟

لا يسمح للمصدر الاحتياطي بتغيير السعر إذا:

- المباراة لا تزال live ولم تنته.
- النتيجة من المصدر الاحتياطي أقل من النتيجة المحلية.
- لم يتم العثور على الفريقين بثقة داخل قاعدة البيانات.
- الحدث قد تم تطبيقه سابقًا بنفس `localeGroupKey`.
- التغيير سيؤدي إلى تكرار هدف أو تكرار تأثير سعري.
- لم يتم تفعيل `applyMarketEvents=true`.

---

## 9) سياسة التعارض بين المصادر

عند التعارض:

1. أثناء المباراة: ISPORTS له الأولوية للـ live.
2. بعد نهاية المباراة: football-data.org له الأولوية لتأكيد النتيجة والحالة.
3. الصور والبروفايلات: TheSportsDB له الأولوية.
4. الأسعار: محرك التسعير الداخلي له الأولوية دائمًا.

---

## 10) سياسة حماية الحصص

- لا يتم استدعاء live provider إلا عند وجود مباريات اليوم أو مباريات قريبة.
- يتم استخدام throttle مع ISPORTS.
- football-data.org يستخدم كطلب مجمع حسب التاريخ أو المسابقة.
- TheSportsDB يستخدم في admin sync أو enrichment، وليس في كل زيارة للواجهة.
- الواجهة تقرأ دائمًا من قاعدة البيانات المحلية.

---

## 11) مبدأ التتبع

أي بيانات تؤثر على السعر يجب أن تكون قابلة للتتبع:

- provider
- providerMatchId
- localMatchId
- eventType
- scoreBefore
- scoreAfter
- priceBefore
- priceAfter
- localeGroupKey

بدون هذه المعلومات، لا يجب إنشاء تأثير سعري تلقائي.

---

## 12) القرار الحالي

الوضع الحالي المعتمد:

**ISPORTS = live source**  
**football-data.org = confirmation and backup source**  
**TheSportsDB = media and profile enrichment source**  
**API-Football = conditional future provider**  
**Database = platform source of truth**  
**Pricing engine = business value layer**

---

## 13) قاعدة تنفيذ مستقبلية

أي تعديل مستقبلي في مصادر البيانات أو تحريك السعر يجب أن يلتزم بهذه الوثيقة أولًا.

إذا احتاج تعديل قادم إلى مخالفة هذه السياسة، يجب تحديث هذه الوثيقة في نفس التعديل مع توضيح السبب.
